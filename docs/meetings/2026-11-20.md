## Kết luận của thầy (nguyên văn Hùng ghi lại)

### 1. Chuyên sâu RAG (framework cho user tự tạo/cấu hình RAG)

Keyword:
- knowledge base: phân tích các lựa chọn kb khác nhau. Ví dụ: vector database, graph database hoặc mix
- phương pháp index
- phương pháp chunking (nhiều phương pháp chunking, làm sao để chọn được phần chunking tối ưu)
- workflow/pipeline của RAG (câu hỏi → detect ngôn ngữ → tìm kiếm knowledge base → ...): xây dựng thành
  module, user kéo thả, input theo trình tự, để tự xây dựng pipeline
- visualize dữ liệu vector (trong biểu đồ vector đặc trưng), visualize graph đồ thị
- hỗ trợ short memory, long memory (lưu trữ các dữ liệu trong cuộc trò chuyện để nâng cao khả năng trả lời)

Thầy nhận xét: **"chunking + pipeline ⇒ khủng"**.

Thầy gợi ý hướng đi: cấu hình được RAG trên giao diện, cho user chọn
- vector database hoặc graph database
- phương pháp chunking hoặc phương pháp index
- cấu hình pipeline (advanced of advanced). Ví dụ: input query → phân tích query → tạo ra query trong
  database → hỏi LLM → step a → step b → step c

### 2. Nhắc lại về routing

- Những bộ MMLU đó là **benchmark**, không phải tiêu chí đánh giá.
- Cần 4–5 kết quả **chỉ số đánh giá** cho mỗi proxy.
- Thầy có nhắc "tool rank tự tính toán chỉ số".

### 3. Ba đóng góp chính của đề tài

1. Mô hình routing và đánh giá mô hình routing ⇒ chọn model.
2. Cung cấp nền tảng để người dùng tự tạo RAG theo dữ liệu tùy biến của họ.
3. Đưa ra một ứng dụng demo triển khai cho đóng góp 1 và 2.

  thầy ở buổi sau.
